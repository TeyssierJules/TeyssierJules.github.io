Work Work-study project presented to a jury 2026

Active Directory audit and hardening

  • Active Directory
  • PingCastle
  • GPO
  • Centreon

Context

According to ANSSI, the French national cybersecurity agency, healthcare is one of the sectors most exposed to cyberattacks. I built an isolated lab that reproduces the Active Directory of a client in this sector. Domain sante-lab.local, domain controller on Windows Server 2019, virtualised on Proxmox.

What I did

  • I introduced four vulnerabilities: SMBv1 enabled, LLMNR enabled, 7-character minimum passwords, an inactive account named ancien.admin.
  • I audited the directory with PingCastle.
  • I hardened the configuration with GPOs and PSOs, following ANSSI guidelines: SMBv1 and LLMNR disabled, 14-character minimum for all users, 15 for privileged accounts, ancien.admin disabled.
  • I ran the audit again to check each fix.
  • I set up Centreon monitoring over SNMP: CPU, memory, disk, with a test alert.

Outcome

I checked every fix: SMBv1 and LLMNR disabled, new password policy applied, ancien.admin disabled. The risk level went down.

What I learned

You don't fix things blindly: before disabling an account, I check what it's used for. And a tool doesn't do everything: Centreon's Windows connectors required a licence, so I configured the metrics by hand.

University Year 2 2026

Stormshield firewall

  • Stormshield
  • NAT
  • Filtering
  • SSL VPN

Context

Working in pairs, we managed the firewall of a fictional company: an internal network, a DMZ with DNS, web, FTP and mail servers, and Internet access. Nine independent labs, each with a specific need. Between labs, we restored a configuration backup.

What I did

  • Traffic logging and reading filter logs
  • NAT: Internet access for the internal network, publishing DMZ servers on public addresses
  • Filtering between zones: access to the DMZ, allowed services to the Internet (web, DNS, FTP, mail, SSH)
  • Targeted rules: blocking FTP for a single host, blocking websites by URL and by country
  • Alarms on a ping or an admin login attempt from outside
  • SSL VPN for a remote user, authenticated against an LDAP directory

I tested every rule from both sides: from the client machine (ping, wget, nslookup, telnet, ftp) and on the firewall (logs, active sessions, tcpdump).

Outcome

I completed all nine labs. I got hands-on with every firewall feature: logging, NAT, filtering, alarms, authentication, VPN.

What I learned

A rule only exists once I've tested it. I wrote my own verification guide: for each rule, the command to run and the expected result.

University Year 2 Solo project

MonCoffreFort Digital vault

  • Java
  • SQLite
  • AES-256-GCM

Context

A project for the Java programming module. I built it alone, working independently. It ended with an exam.

What I did

  • Access by PIN code. The PIN is never stored in plain text: only its SHA-256 hash is saved.
  • Documents encrypted with AES-256-GCM in the SQLite database
  • Access recovery through a secret question
  • Local SQLite database: documents, categories, date added saved automatically
  • Search and sort with prepared statements, to block SQL injection
  • Mandatory confirmation before any deletion
  • Adding images from the gallery
  • One-click copy of sensitive data, without showing it on screen

Outcome

Application finished and presented at the Java exam.

What I learned

SHA-256 alone isn't enough to protect a short PIN. Today, I would use a slow, salted algorithm such as bcrypt or Argon2.
